# نقش اپراتور RSP

مدیر از «همه کاربران ← ایجاد یا ویرایش کاربر»، نقش «اپراتور» را انتخاب می‌کند و کلاس‌های تحت نظارت را ثبت می‌کند. حساب‌های قبلی تا زمان تخصیص، در بخش‌های محدود به کلاس نتیجه‌ای دریافت نمی‌کنند. اطلاعیه برای دانش‌آموزان کلاس‌های انتخاب‌شده از سال فعال منتشر می‌شود.

اپراتور همه گروه‌های زبان را در بخش نظارت می‌بیند. کلاس‌های آنلاین فعال مدرسه و زبان از منوی کلاس‌های آنلاین در دسترس‌اند. در BigBlueButton ورود با نقش Moderator انجام می‌شود و گزارش زنده از مسیر حضور و غیاب قابل مشاهده است. تنظیم ثبت رویدادهای حضور در سامانه در اختیار مدیر باقی می‌ماند.

## اسکای‌روم

برای ورود مستقیم با نقش اپراتور، نشانی کامل API سرویس اسکای‌روم را در متغیر محیطی `RSP_SKYROOM_API_URL` روی سرور تنظیم کنید. این نشانی حاوی کلید است و باید فقط در تنظیمات محرمانهٔ سرویس RSP نگهداری شود. لینک هر کلاس باید نشانی عمومی همان اتاق به شکل `https://www.skyroom.online/ch/<service>/<room>` باشد. RSP شناسهٔ اتاق را از API می‌گیرد و لینک ورود دو دقیقه‌ای مخصوص اپراتور می‌سازد. در صورت خالی بودن تنظیم API، اتاق با لینک عادی باز می‌شود و نقش با حساب اسکای‌روم تعیین می‌شود. گزارش زندهٔ موجود RSP برای BigBlueButton است.

[راهنمای رسمی وب‌سرویس اسکای‌روم](https://data.skyroom.online/help/webservice.html)

## استقرار

نسخهٔ وب را روی پایهٔ آزمون آنلاین وب و نسخهٔ PWA را روی پایهٔ PWA مستقر کنید. پیش از جایگزینی فایل‌ها، تفاوت‌های سرور را با پایهٔ شاخه بررسی کنید. پروژه از استقرارهای مرحله‌ای استفاده کرده و فایل‌های سرور ممکن است تغییرهای اختصاصی داشته باشند. مهاجرت‌های ادغام‌شدهٔ زبان و حضور و غیاب با نام قبلی ادامه پیدا می‌کنند.

از فایل‌های برنامه، تنظیم Nginx و پایگاه داده نسخهٔ پشتیبان بگیرید. بعد از به‌روزرسانی کد، در محیط production دستورهای `migrate`، `check --deploy` و `collectstatic` را اجرا کنید و سرویس را راه‌اندازی کنید. کارنامه‌های آزمون همچنان در مسیر فعلی ذخیره می‌شوند و سرویس زمان‌بندی آزمون باید فعال بماند.

اگر Nginx برای `/media/` از alias مستقیم استفاده می‌کند، مسیرهای زیر باید با همان تنظیمات پراکسی Gunicorn در `location /` به Django ارسال شوند. در غیر این صورت مسیر قدیمی فایل می‌تواند کنترل دسترسی Django را دور بزند. برای نمونه، در همان server block و پیش از regexهای عمومی رسانه، از تطبیق زیر استفاده کنید. در صورت وجود `location ^~ /media/` آن را به `location /media/` تبدیل کنید تا تطبیق regex اعمال شود.

```nginx
location ~ ^/media/(assignments|educational_materials|language_assignments|language_materials|report_cards)/ {
    # Use the same proxy_pass and proxy headers as this server's location /.
}
```

پس از `nginx -t` و reload، آدرس قدیمی یک فایل آموزشی و یک کارنامه را با حساب اپراتور برای کلاس مجاز، کلاس غیرمجاز و نشست بدون ورود بررسی کنید. نتیجهٔ مورد انتظار به‌ترتیب دریافت فایل، ۴۰۴ و انتقال به ورود است. همین مسیرها از داخل رابط RSP هم کنترل می‌شوند.

برای آزمون‌های قبلی، شناسهٔ کلاس از نام ذخیره‌شده و ثبت‌نام قابل تطبیق در زمان ایجاد آزمون بازیابی می‌شود. رکوردهای مبهم، از جمله مواردی که انتخاب از گروه زبان قابل رد نیست، در دید اپراتور نمایش داده نمی‌شوند و در دسترس مدیر باقی می‌مانند.
